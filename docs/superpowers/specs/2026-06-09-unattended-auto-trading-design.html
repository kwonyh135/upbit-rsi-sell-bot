KRW-HUNT 무인 자동매매

업비트 5분봉 RSI 분할매매 전략을 Windows 노트북에서 상시 실행하고, 거래·오류·시작 및 종료 상태를 텔레그램으로 알리는 설계입니다.

시장 KRW-HUNT 완료된 5분봉 RSI 14 텔레그램 알림 Windows 자동 시작
빠른 이동 핵심 요약 매매 전략 실행 구조 주문 안전장치 급락 비상 보호 텔레그램 알림 오류 대응 Windows 운영 명령어 검증 계획 제외 범위

핵심 요약

현재 상태 승계 저장된 phase부터 이어서 실행
매수 자금 각 시점의 전체 KRW 잔고 사용
주문 방식 조건 충족 시 확인 입력 없이 자동 주문
중복 방지 완료 봉·주문 UUID·pending 상태 저장
중요: 이 모드는 실제 자산으로 시장가 주문을 자동 전송합니다. 구현 후에도 시뮬레이션과 텔레그램 알림 검증을 통과하기 전에는 자동 live 작업을 활성화하지 않습니다.

4단계 매매 전략

RSI는 완료된 5분봉만 사용합니다. 진행 중인 봉에는 반응하지 않으며, 동일한 완료 봉은 한 번만 처리합니다.

1 1차 매도

현재 보유 HUNT 수량의 50%를 시장가 매도합니다.

RSI ≥ 60
2 2차 매도

남아 있는 HUNT 수량을 전부 시장가 매도합니다.

RSI ≥ 65
3 1차 매수

해당 시점에 사용 가능한 전체 KRW 잔고의 50%를 사용합니다.

RSI ≤ 45
4 2차 매수

해당 시점에 남아 있는 전체 KRW 잔고를 사용합니다.

RSI ≤ 40
봇 실행 후 새로 입금된 KRW도 다음 매수 단계의 사용 가능 잔고에 포함됩니다. 수동 확인 문구인 BUY KRW-HUNT와 SELL KRW-HUNT는 무인 모드에서 사용하지 않습니다.

실행 구조와 상태 저장

무인 실행 방식

  • 기존 수동 live 명령은 그대로 유지합니다.
  • 별도 명령 run-auto-5m으로만 무인 거래를 시작합니다.
  • 새 완료 5분봉이 생겼을 때만 RSI와 주문 조건을 평가합니다.
  • 현재 저장된 phase를 읽어 중단 지점부터 재개합니다.

영구 저장 항목

  • 현재 전략 phase
  • 마지막으로 평가한 완료 봉 시각
  • 미해결 주문 UUID와 예정된 다음 phase
  • 복구 및 알림에 필요한 최근 거래 정보

상태 파일은 임시 파일에 먼저 쓴 뒤 원본을 교체하는 방식으로 저장하여, 전원 종료나 프로세스 중단 중에도 불완전한 JSON이 남지 않도록 합니다.

주문 안전장치

주문 전 확인

  • 새로 완료된 5분봉에서 발생한 신호인지 확인
  • 현재 phase와 주문 종류가 일치하는지 확인
  • 주문 수량 또는 KRW 금액이 0보다 큰지 확인
  • 업비트 최소 주문금액과 지원 주문 유형 확인
  • 아직 해결되지 않은 pending 주문이 없는지 확인

주문 전송 후 처리

  1. 업비트에서 받은 주문 UUID를 pending 상태로 즉시 저장합니다.
  2. 업비트 주문 조회 API로 최종 상태와 실제 체결 수량·금액을 확인합니다.
  3. 체결 완료가 확인된 경우에만 다음 phase로 전환합니다.
  4. 체결 여부를 판단할 수 없으면 pending 상태를 유지하고 신규 주문을 중단합니다.
타임아웃이나 모호한 API 응답이 발생해도 주문을 임의로 재전송하지 않습니다. 재시작 시 저장된 주문 UUID를 먼저 조회하여 해결한 뒤에만 다음 신호를 처리합니다.

급락 비상 보호

비상 보호 조건은 모든 RSI 매수·매도 조건보다 먼저 평가하며, 발동 시 일반 전략 처리를 즉시 차단합니다.

감지 조건

  • 10초마다 현재 가격과 최근 1분봉 5개의 최고가를 비교
  • 현재가가 최근 5분 최고가보다 7% 이상 하락
  • 또는 업비트 평균매수가보다 10% 이상 하락
  • 같은 위험 조건이 10초 간격으로 2회 연속 확인되어야 확정
  • 정상 가격이 한 번 확인되면 연속 횟수를 0으로 초기화

발동 후 동작

  • 사용 가능한 HUNT 전량 시장가 매도
  • 주문 UUID를 pending 상태로 저장하고 체결 완료 확인
  • 체결 완료 후 emergency_halt 상태로 전환
  • 자동 매수와 일반 RSI 매매 전부 중단
  • 로컬 수동 해제 명령으로만 sell_1 복귀

1분봉 데이터가 비어 있거나 오래됐거나 5개보다 부족하면 하락률을 추정하지 않습니다. 해당 감지 주기를 건너뛰고 오류를 기록·알림합니다.

텔레그램 알림

환경 변수

  • TELEGRAM_BOT_TOKEN
  • TELEGRAM_CHAT_ID

토큰과 chat ID는 .env에만 저장하고 코드나 로그에는 출력하지 않습니다.

알림 대상

  • 봇 시작: 현재 phase와 잔고
  • 정상 종료
  • 주문 제출
  • 주문 체결 완료
  • API·네트워크·상태·주문 확인 오류
  • 오류 상태에서 정상 복구

거래 알림에는 액션, RSI, 봉 시각, 가격, 실제 체결 수량과 금액, 주문 UUID, 다음 phase를 포함합니다. 동일 오류의 반복 알림은 제한합니다.

텔레그램 전송 실패는 거래 상태와 분리합니다. 알림이 실패해도 완료된 거래를 되돌리거나 같은 주문을 다시 보내지 않습니다.

오류 대응

  • 일시적인 시세·계좌 API 오류는 제한된 지수 백오프로 재시도합니다.
  • 반복 실패 시 프로세스는 유지하되 신규 신호 처리를 일시 중지합니다.
  • 주문 결과가 불명확하면 reconciliation 모드로 들어가 신규 주문을 차단합니다.
  • 상태 파일이 없거나 잘못된 경우 거래를 중단하고 오류 알림을 전송합니다.
  • 텔레그램 장애는 로그에 남기고 별도로 재시도하며 거래 엔진은 계속 동작합니다.
  • 예상하지 못한 예외는 시각과 함께 로그에 기록하고 가능한 경우 오류 알림을 보냅니다.

작업 스케줄러

  • worktree 폴더를 작업 디렉터리로 사용
  • 현재 확인된 번들 Python 실행기 사용
  • 실패 시 일정 지연 후 자동 재시작
  • 봇 프로세스 중복 실행 방지
  • stdout·stderr 순환 로그 저장

노트북 전원

  • AC 전원 연결 중 절전 모드 해제
  • 인터넷 연결 유지
  • Windows 업데이트 후 재로그인 여부 확인
  • 노트북 종료·절전 중에는 거래 불가

명령어 구성

기존 명령은 유지합니다.

  • watch-buyback-5m --dry-run
  • watch-buyback-5m --live
  • sync-buyback-state

무인 자동매매는 별도 명령으로 분리합니다.

python -m huntbot run-auto-5m --dry-run
python -m huntbot run-auto-5m --dry-run --once
python -m huntbot run-auto-5m --live

모드 플래그는 필수이며, --once는 주문 없는 검증 주기 1회 후 종료합니다. 수동 live 명령을 실수로 무인 모드로 전환하지 않도록 명령 경계를 유지하고, 작업 스케줄러도 실제 주문을 위해 --live를 명시해야 합니다.

실제 자동 live 활성화 전 체크리스트

  1. 전체 자동화 테스트를 실행하고 모두 통과시킵니다.
  2. 주문을 보내지 않는 무인 시뮬레이션 모드를 실행합니다.
  3. 텔레그램 시작·가상 거래·오류·복구 메시지를 확인합니다.
  4. 업비트 실제 잔고와 저장된 phase를 대조합니다.
  5. 모든 확인 이후에만 작업 스케줄러의 무인 live 작업을 활성화합니다.
